## cPanel Deployment Strategy

### Recommended: Option A — cPanel Node.js App (standalone output)

**Why:** The app uses NextAuth (server-side session handling), Prisma with SQLite (server-side DB reads/writes), and API routes under `src/app/api/` (13 route groups). It cannot be a static export. Option B is ruled out.

Option C (Git Version Control + post-receive hooks) is a valid secondary mechanism and is included in the pipeline design — the GitLab CI/CD pipeline will SSH into cPanel and trigger a `git pull` + restart. This gives you the best of both: GitLab handles build/test/lint, cPanel pulls the pre-built artifact.

### How Option A is configured

1. In cPanel, go to **Setup Node.js App** and create a new app:
   - **Node.js version:** 20.x or 22.x
   - **Application mode:** Production
   - **Application root:** `zelaki-sacco` (the folder you deploy into under your home dir)
   - **Application URL:** your domain (e.g. `zelakisacco.com`)
   - **Application startup file:** `.next/standalone/server.js`

2. Set environment variables in the Node.js app panel (see Environment Variables section).

3. The startup file is `.next/standalone/server.js`. cPanel's Node.js app manager will call it with `node .next/standalone/server.js`. The `PORT` env var must be set to whatever port cPanel assigns (shown in the panel as "Passenger port" or similar).

4. Static assets in `.next/static` and `public/` must be copied alongside `server.js` as the build script already does.

## GitLab CI/CD Pipeline Plan

### Stages

```
lint → build → deploy
```

### Stage details

**lint**
- Runner: `node:20-alpine` or `node:22-alpine` with Bun installed
- Runs `bun install --frozen-lockfile` then `bun run lint`
- Fails fast before wasting build time

**build**
- Runner: same image
- Runs `bun install --frozen-lockfile` then `bun run build` (which invokes `next build` and copies static/public into `.next/standalone/`)
- Archives `.next/standalone/`, `.next/static/`, and `public/` as a GitLab artifact passed to the deploy stage
- Sets `NEXT_TELEMETRY_DISABLED=1`

**deploy**
- Triggered only on the `main` branch
- SSHs into the cPanel server and:
  1. `git pull origin main` (or rsync/scp the built artifact)
  2. `cd ~/zelaki-sacco && bun install --production`
  3. `npx prisma generate && npx prisma migrate deploy`
  4. Restarts the Node.js app via cPanel API or a `touch tmp/restart.txt` (Passenger restart mechanism)

|----------|-------------|-----------|--------|

SSH-based deployment: GitLab runner SSHs to the cPanel host using `SSH_PRIVATE_KEY`, pulls the latest code, runs migrations, and restarts via Passenger's `tmp/restart.txt` mechanism (which every cPanel Node.js app supports).

## Database Considerations

**Current engine:** SQLite (`provider = "sqlite"` in `prisma/schema.prisma`)

**Current DB file path:** `file:/home/z/my-project/db/custom.db` — this is a hardcoded path pointing to a local dev environment. It must be updated to the actual cPanel home directory path before deployment.

### SQLite on cPanel shared hosting — flags

| Item | Status |
|------|--------|
| Works on shared hosting | ✅ SQLite is a file — no separate DB server needed |
| Concurrency | ⚠️ SQLite has write-lock contention under concurrent requests. For a SACCO with moderate traffic this is acceptable, but monitor it |
| File path | ⚠️ **Must be updated** — `/home/z/my-project/db/custom.db` does not match cPanel's actual home directory. Use the real path, e.g. `/home/zelakiuser/zelaki-sacco/db/custom.db` |
| Backups | ⚠️ You must set up a cron job or manual download — SQLite is a single file, easy to back up via File Manager |
| Prisma migrations in production | ✅ Use `prisma migrate deploy` (not `migrate dev`) in deployment |
| PostgreSQL/MySQL migration | ⚠️ Recommended if the host provides MySQL (almost all cPanel hosts do). MySQL gives better concurrency, easier backups, and no file-path issues. Prisma makes switching the provider straightforward — the schema models stay the same, only the `datasource` block changes |

**How Prisma migrations should run:**
- In development: `bun run db:migrate` (creates migration files)
- In CI build stage: `npx prisma generate` (generates the client)
- In deploy stage on cPanel: `npx prisma migrate deploy` (applies pending migrations without prompts)
- Initial seed (first deploy only): `node prisma/seed.ts && node prisma/seed-menu.ts`

**Never** run `prisma migrate dev` or `prisma migrate reset` on the production server.

## Step-by-Step Deployment Guide

### 1. Prerequisites

- cPanel hosting plan with **Node.js support** (look for "Setup Node.js App" in cPanel). EasyApache 4 with the Node.js Selector, or CloudLinux-based hosts, provide this.
- Node.js 20.x or 22.x available in the Node.js Selector.
- SSH access enabled for your cPanel account.
- GitLab account with your project repository pushed.
- Bun installed on the **build machine** (GitLab runner). The server only needs Node.js; Bun is used in the runner.

---

### 2. Set up cPanel Node.js App

1. Log in to cPanel → find **Setup Node.js App** (or "Node.js Selector").
2. Click **Create Application**.
3. Fill in:
   - **Node.js version:** 20.x (or 22.x)
   - **Application mode:** Production
   - **Application root:** `zelaki-sacco` (this will be `~/zelaki-sacco` on the server)
   - **Application URL:** your domain, e.g. `zelakisacco.com`
   - **Application startup file:** `.next/standalone/server.js`
4. Click **Create**. Note the **application port** shown — you'll set this as `PORT` in the env vars.
5. Use the **Terminal** button (or SSH) to initialize the directory:
   ```bash
   mkdir -p ~/zelaki-sacco/db
   mkdir -p ~/zelaki-sacco/tmp
   ```

---

### 3. Configure GitLab repository and CI/CD variables

1. Push your code to GitLab if you haven't already:
   ```bash
   git remote add origin https://gitlab.com/YOUR_USERNAME/zelaki-sacco.git
   git push -u origin main
   ```
2. Generate an SSH key pair for CI/CD deployment (do this on your local machine):
   ```bash
   ssh-keygen -t ed25519 -C "gitlab-cicd-deploy" -f ~/.ssh/gitlab_deploy_key -N ""
   ```
3. Add the **public key** (`~/.ssh/gitlab_deploy_key.pub`) to cPanel:
   - cPanel → **SSH Access** → **Manage SSH Keys** → **Import Key** → paste the public key content.
   - Authorize it.
4. In GitLab, go to your project → **Settings → CI/CD → Variables** → expand and add:

   | Key | Value | Protected | Masked |
   |-----|-------|-----------|--------|
   | `SSH_PRIVATE_KEY` | Contents of `~/.ssh/gitlab_deploy_key` (the private key) | ✅ | ✅ |
   | `CPANEL_HOST` | Your server hostname, e.g. `server123.hostingprovider.com` | ✅ | No |
   | `CPANEL_USER` | Your cPanel username | ✅ | No |
   | `CPANEL_APP_DIR` | `/home/YOUR_CPANEL_USER/zelaki-sacco` | No | No |
   | `DATABASE_URL` | `file:/home/YOUR_CPANEL_USER/zelaki-sacco/db/custom.db` | ✅ | No |
   | `NEXTAUTH_URL` | `https://yourdomain.com` | ✅ | No |
   | `NEXTAUTH_SECRET` | Generate with: `openssl rand -base64 32` | ✅ | ✅ |

### 4. Create `.gitlab-ci.yml`

Create this file at the project root (`c:\Users\meseretak\Desktop\Website\Zelaki-Sacco\.gitlab-ci.yml`):

```yaml
# Zelaki Sacco — GitLab CI/CD Pipeline
# Stages: lint → build → deploy
# Deploy triggers only on the main branch via SSH to cPanel

image: node:22-slim

stages:
  - lint
  - build
  - deploy

variables:
  NEXT_TELEMETRY_DISABLED: "1"
  BUN_VERSION: "1.1.42"

# ─── Shared setup ────────────────────────────────────────────────────────────
.install_bun: &install_bun
  before_script:
    - apt-get update -qq && apt-get install -y -qq curl unzip git
    - curl -fsSL https://bun.sh/install | bash -s "bun-v${BUN_VERSION}"
    - export PATH="$HOME/.bun/bin:$PATH"
    - bun --version

# ─── Lint ────────────────────────────────────────────────────────────────────
lint:
  stage: lint
  <<: *install_bun
  script:
    - export PATH="$HOME/.bun/bin:$PATH"
    - bun install --frozen-lockfile
    - bun run lint
  cache:
    key:
      files:
        - bun.lockb
    paths:
      - node_modules/
  only:
    - main
    - merge_requests

# ─── Build ───────────────────────────────────────────────────────────────────
build:
  stage: build
  <<: *install_bun
  script:
    - export PATH="$HOME/.bun/bin:$PATH"
    - bun install --frozen-lockfile
    - bun run build
    # Verify standalone output was produced
    - test -f .next/standalone/server.js || (echo "ERROR: standalone build missing server.js" && exit 1)
  artifacts:
    paths:
      - .next/standalone/
      - .next/static/
      - public/
      - prisma/
      - package.json
      - bun.lockb
    expire_in: 1 hour
  cache:
    key:
      files:
        - bun.lockb
    paths:
      - node_modules/
    policy: pull
  only:
    - main

# ─── Deploy ──────────────────────────────────────────────────────────────────
deploy:
  stage: deploy
  image: alpine:latest
  before_script:
    - apk add --no-cache openssh-client rsync
    # Set up SSH
    - eval $(ssh-agent -s)
    - echo "$SSH_PRIVATE_KEY" | tr -d '\r' | ssh-add -
    - mkdir -p ~/.ssh && chmod 700 ~/.ssh
    - ssh-keyscan -H "$CPANEL_HOST" >> ~/.ssh/known_hosts
    - chmod 644 ~/.ssh/known_hosts
  script:
    # 1. Sync the built artifact to the server
    - |
      rsync -az --delete \
        --exclude='db/' \
        .next/standalone/ "$CPANEL_USER@$CPANEL_HOST:$CPANEL_APP_DIR/.next/standalone/"
    - |
      rsync -az --delete \
        .next/static/ "$CPANEL_USER@$CPANEL_HOST:$CPANEL_APP_DIR/.next/standalone/.next/static/"
    - |
      rsync -az --delete \
        public/ "$CPANEL_USER@$CPANEL_HOST:$CPANEL_APP_DIR/.next/standalone/public/"
    - |
      rsync -az \
        prisma/ "$CPANEL_USER@$CPANEL_HOST:$CPANEL_APP_DIR/prisma/"
    - scp package.json "$CPANEL_USER@$CPANEL_HOST:$CPANEL_APP_DIR/package.json"
    - scp bun.lockb "$CPANEL_USER@$CPANEL_HOST:$CPANEL_APP_DIR/bun.lockb" 2>/dev/null || true

    # 2. On the server: install prod deps, generate Prisma client, run migrations, restart
    - |
      ssh "$CPANEL_USER@$CPANEL_HOST" bash << 'ENDSSH'
        set -e
        cd "$CPANEL_APP_DIR"

        echo "==> Installing production dependencies..."
        npm install --production --legacy-peer-deps

        echo "==> Generating Prisma client..."
        npx prisma generate

        echo "==> Running database migrations..."
        npx prisma migrate deploy

        echo "==> Restarting Node.js app via Passenger..."
        mkdir -p tmp
        touch tmp/restart.txt

        echo "==> Deploy complete!"
      ENDSSH
  environment:
    name: production
    url: $NEXTAUTH_URL
  only:
    - main
  when: on_success
```

**Important notes about this pipeline:**
- The SSH command uses a heredoc. The `$CPANEL_APP_DIR` on the server side is passed as an environment variable — make sure the GitLab variable `CPANEL_APP_DIR` is set to the absolute path.
- `touch tmp/restart.txt` works with cPanel's Passenger integration. If your host uses a different restart mechanism (e.g., cPanel API call), adjust accordingly.
- The pipeline does **not** commit secrets — all secrets are in GitLab CI/CD variables only.
